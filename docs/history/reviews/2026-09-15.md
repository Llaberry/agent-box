## 2. The guard mutation

**"Can my new guard actually fail?"**

⛔ **Planted the defect each guard exists to catch, and read the exit code
unpiped.** Fourteen plants.

| plant | guard | result |
| --- | --- | --- |
| a link to a file that does not exist | links | exits 1, naming file and target |
| an em dash | markers | exits 1 |
| a character outside the five | markers | exits 1 |
| 60 markers appended to one page | markers | exits 1, reporting density 53.7 |
| a 15-word sentence duplicated across two pages | one-home | exits 1, naming both |
| ⭐ the same sentence duplicated into the history directory | one-home | **exits 0, correctly.** The exemption works. |
| a new page nothing links to | orphans | ⛔ **exited 0. DID NOT FIRE.** |
| a literal escape byte | control-bytes | exits 1 |
| a co-author trailer naming a model | commit hook | ⛔ **exited 2 on everything. BROKEN.** |
| a generated-with line | commit hook | after the fix: exits 1 |
| a vendor name in the body | commit hook | after the fix: exits 1 |
| a robot glyph | commit hook | after the fix: exits 1 |
| a clean message | commit hook | after the fix: exits 0 |
| the trailer inside a git comment line only | commit hook | after the fix: exits 0, correctly |

### ⛔ Finding 1: the orphan check did not fire on a real orphan

**This is the exact failure this lens exists to catch**, and the methodology's
own worked example is a scan reporting "no orphans" over the orphan it was
written to find, twice.

**Cause:** a link to a directory was marking **every** markdown file inside it
as linked. Three pages link to `docs/`, so every page directly under `docs/` was
permanently unreportable.

**Fix:** a link to a directory marks that directory's own `README.md` and
nothing else. ⭐ **Re-planted and the guard now exits 1.**

⚠ **The guard had been green over this tree for the whole session**, and green
was meaningless for that check the entire time.

### ⛔ Finding 2: the commit-message hook was broken

Copied from the template, it called a shell script at a path this repository
does not ship, so it exited 2 on **every** message.

Two consequences, and the second is the one that reads as safe:

1. no attribution was ever checked, so the rule it holds was unenforced;
2. ⚠ it fails closed, so the repository could not be committed to at all while
   the hook was armed.

**Fix:** rewritten self-contained in POSIX shell, matching a co-author trailer,
a generated-with line, a robot glyph and a list of vendor names, stripping git's
own comment lines first. Mutation-proved six ways above.

⛔ **The general finding: copying a guard copies its dependencies**, and a guard
whose dependency is missing reports "could not run" rather than "failed", which
is correct and is still a guard that is not guarding.

**What this pass did NOT look at:** whether a page is reachable (pass 1), or
whether any citation is true (pass 3).

## 3. The claim audit

**"Which sentence here is not backed by an artefact I can point at?"**

⛔ **Re-derived every load-bearing citation and every number against the corpus
at the pinned commits.** 61 checks.

### Citations: 59 of 61 confirmed, 2 wrong

| claim | result |
| --- | --- |
| 31 line-range citations into four reference trees | ⛔ **2 wrong**, corrected: one off by four lines, one off by seventeen. 29 confirmed. |
| 30 quotations from three harness projects' documentation | ⭐ **all 30 confirmed verbatim.** |

⚠ **And a finding about the checker rather than the claims:** four quotations
first reported absent were present and verbatim, wrapped across lines in the
source. ⛔ **A citation check that matches raw text produces false failures, and
a reviewer who trusts one edits a correct quotation into a wrong one.** Recorded
as a requirement in T-054.

### Numbers: 4 of 8 wrong

⛔ **Every one was a number written from memory rather than measured**, which is
the pattern worth naming.

| claim | written | measured |
| --- | --- | --- |
| the reference's `src/` line count | roughly 21,000 | **26,552** |
| files in its sandbox directory | twelve | **14** |
| tracked files in this repository | 47 | **64** |
| the share of that tree that is task surface | "about two thirds" | **56 per cent** (20,005 of 35,471) |
| its total line count | about 35,500 | 35,471, confirmed |
| its sandbox surface | 3,034 lines | confirmed |
| two reference files' line counts | 155 and 150 | both confirmed |

All four corrected in place, with the per-directory measurement written out so
the ratio can be re-derived rather than re-asserted.

### The contradiction this pass found and kept

⭐ **A reference's documentation and its code disagree about what its agent
holds**, and the code wins. The page states the weaker case as though it were
the only one. That disagreement is recorded as a finding rather than resolved
silently, because it is worth more than either source alone.

**What this pass did NOT look at:** whether the sweeps missed content the corpus
contains, which no pass here did. ⚠ **Nothing was read a second time**, and a
second reading is what found the fifth correction in another project's
withdrawn-claims list.
